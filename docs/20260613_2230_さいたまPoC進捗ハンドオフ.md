## ローカルで動かす手順

```bash
git fetch origin poc/saitama-mirai-gikai
git checkout poc/saitama-mirai-gikai
pnpm install

npx supabase start          # ローカルDB（Postgres :54432）
pnpm seed                   # 検証データ投入（現状は国会版データ）
pnpm dev                    # web :3000 / admin :3001

cd observability
docker compose up -d        # Grafana :3002（初期 admin/admin）
```

- Grafana ダッシュボード「みらい議会＠さいたま PoC オーバービュー」が自動で出る。
- **運用開始前はパネルがほぼ空**。議案公開・インタビュー実施でデータが入ると埋まる。

## 引き継ぎメモ（調査で分かった事実）

- ローカル DB ポートは **54432**（`supabase/config.toml` の `db.port`。Supabase 既定の 54322 ではない）。
- `biome.json` の lint/format 対象は `web/src` `admin/src` `tests` のみ。`docs/` `observability/` は対象外。
- コスト計測の生命線は `chat_usage_events`（`cost_usd`, `model`, `total_tokens`, `occurred_at`, `session_id`）。
  `session_id` は `interview_sessions.id::text` と結合する。
- `bills.publish_status`（draft/published/coming_soon）と `published_at` で公開状態を管理。
- 既存シードは国会版（ガソリン税法案・船荷証券法案など）が大量に作り込まれているため、
  さいたま市版シードは「丸ごと置換」か「別データセット追加」かを先に方針決めするとよい。
