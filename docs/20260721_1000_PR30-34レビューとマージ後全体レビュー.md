## 統合後の全体レビュー：不足点・追加考慮の候補

### 優先度高め

- **本家developの未追従分**: PoCへの本家取り込みはPR #23が最後で、その後 `origin/develop` は33コミット以上進んでいる。特に「インタビュー要約の引用を逐語に限定（#842）」「トピック分析対象を公開済み意見に限定（#843）」は品質・安全系の修正であり、PoCで市民向けにインタビュー/トピック分析を動かすなら取り込む価値が高い。
- **取り込みデータの鮮度・削除検知なし**: `assembly_documents` はupsertのみのため、DiscussCabinet側で削除・移動された文書がDBに残り続ける。会期中は資料が追加されていくので、「同じサブツリーの再取り込み時に、クロール結果に現れなかった行を削除する」差分同期が次の増分候補（現状は `imported_at` で古さの判別のみ可能）。

### 中程度

- **AI出力の用語一貫性**: PR #30で据え置いたAIプロンプト内の「法案」（interview-config / topic-analysis / simulation）は、AIの生成文にも「法案」が混ざる原因になる。市民向け出力の用語統一として、次の用語対応の本命はここ。
- **`HOUSE_LABELS`（衆議院/参議院）**: web/admin両方に残存。enum・DBカラム `originating_house` の再設計（一院制対応）が必要で、既知の増分3以降課題のまま。

### PoC許容（記録のみ）

- 検索は `title ILIKE '%…%'` のためインデックスが効かないが、現規模（数千件想定・`MAX_CRAWL_DOCUMENTS`=5000ガードあり）では問題なし。増えたら `pg_trgm` GINインデックスを検討。
- クロール上限超過時は部分保存せずthrowする仕様（PR本文に明記済みの割り切り）。クロール自体は200ms待機+深さ/件数ガードがあり、負荷配慮は妥当。
- MCPエンドポイントは `withMcpAuth(required: true)` でトークン必須になっており、認証面の穴はない。
